### 2.1. FEEDBACK — правила работы

#### Не трогать аккордеон-код в `acordion-menu.js`
В `src/js/acordion-menu.js` уживаются две независимые логики:
1. Делегация/привязка кликов на `.acc__head` для раскрытия `.acc` — затрагивает
   аккордеоны по **всему сайту** (не только в калькуляторах).
2. IIFE с `applyMobileLayout` — скрывает `.grid-column-main` / `.grid-column-sidebar`
   на мобилке.

Когда правишь (2), **нельзя задевать (1)** — даже «безобидно» переписывать на
делегирование. Менять стиль аккордеона можно, только если пользователь явно попросил.
**Почему:** пользователь явно остановил рефакторинг — код используется на других
страницах, риск регрессий высок.
**Как применять:** изменения логики mobile-скрытия колонок выноси в **отдельный
JS-файл**. Имя файла должно идти **после** `acordion-menu.js` в алфавитном порядке
(gulp склеит их в `main.js` через `gulp-concat`) — чтобы аккордеон навесил слушатели
на `.acc__head` до detach контейнера из DOM.

#### Одноразовые скрипты не сохранять в репо
Если задача разовая (сгенерировать файл, посчитать diff, миграция данных) — не
создавать `scripts/`-папку или `.mjs/.js` в репозитории. Использовать `%TEMP%` /
`~/.cache` или `node -e "..."`. Остаётся только файл-результат, скрипт — нет.
**Почему:** пользователь явно остановил создание `scripts/diff-css.mjs` — нужен только
итоговый файл, не оснастка.
**Как применять:** перед тем как класть утилитарный скрипт в репо — спросить себя:
«это часть рабочего процесса (npm/CI/обычная задача мейнтейнера) или разовое действие?»
Если второе — выполнять вне проекта.

### 2.2. PROJECT — ключевые решения

#### Расчёты калькуляторов — на чистом клиентском JS, офлайн
Инженерные расчёты в `calc-*.pug` реализованы на чистом клиентском JavaScript, офлайн —
вся математика в браузере, без сетевых запросов.
**Почему:** источник логики — декомпилированное Android-приложение TLV Steam Toolbox
(`formulas/tlv_app_reverse/`). Клиент хочет офлайн-аналог. 2026-06-05 пользователь
явно выбрал JS-офлайн вместо AJAX-бэкенда.
**Конфликт решений:** ранее программист проекта говорил про Python-бэкенд через AJAX.
Пользователь переопределил в пользу JS. Возможен риск двух реализаций — свериться
с программистом.
**Как применять:** математику писать в `src/js/*.js` обычными скриптами (IIFE/глобалы,
БЕЗ import/export — файлы конкатенируются). Три куска логики не попали в извлечённый
`calculators.json` и восстановлены стандартными корреляциями: (1) свойства пара —
IAPWS-IF97 на JS; (2) трение λ — Колбрук-Уайт/Дарси; (3) экв. длины фитингов —
K-факторы. Видимые формулы из `calculators.json` = спецификация. В `units.json`
коэффициентов нет (только символы) — таблицу множителей собираем сами, с учётом
abs/gauge.

## 3. Архитектура движка калькуляторов (детально)

> Это самый большой пласт знаний. Источник — память `project_calc_engine_pattern`.
> Перед правками сверяйся с актуальным кодом в `src/js/`.

### 3.1. Модули (`src/js/`, конкатенируются в `build/js/main.js` по алфавиту, БЕЗ import/export)

- **`calc-steam-if97.js`** → `window.SteamProps`: IAPWS-IF97 области 1/2/4 + вязкость
  (IAPWS 2008). Сверен со всеми контрольными точками стандарта. Внутри: p в МПа, T в К.
  ⚠️ Вязкость жидкой воды (высокая плотность) глючит — для пара корректна.
- **`calc-units.js`** → `window.Units.toSI/fromSI(value, category, symbol)`. Категории:
  pressureAbs(→МПа, abs/gauge), dPress(→Па), temp(→К), massFlow(→кг/ч), length(→м),
  velocity(→м/с) и др. symbol = текст единицы как в `.form-radio-name`. Также
  `window.Units.parseNum` (нормализует запятую) и `Units.list()` (курируемый список
  единиц для конверторов).
- **`calc-pipes-data.js`** → `window.PIPE_TABLE[gradeIdx]` (0..7), сгенерирован из
  `pipes.json` (node-скрипт разовый, не в репо).
- **`calc-formulas.js`** → `window.CALC['<код>'](inpSI)` возвращает выходы в СИ.
  Глобалы (SteamProps/PIPE_TABLE) резолвятся ЛЕНИВО внутри функций. Трение:
  Дарси+Колбрук-Уайт, ε по умолч. 0.05 мм. Подбор трубы: наименьшая, где Δp ≤ допуст.
- **`calc-engine.js`** → на submit формы `[data-calc]` читает `[data-var]`/`[data-cat]`,
  конвертит в СИ, зовёт CALC, рисует `[data-out]`. Единицу берёт из ТЕКСТА КНОПКИ
  `.dropdown--measure .dropdown__button` (не из `:checked`!).

### 3.2. Разметка `calc-N.pug`

- Форма `(data-calc="код")`; класс трубы `.dropdown(data-var="pipeGrade" data-type="grade")`;
  инпуты `data-var` + `data-cat`; фитинги `data-var="fit.obsFlo|thruFlo|check|elbow"`;
  строки результата `data-out` + `data-cat`. Селекты изоляции: `data-type="select"`.
  Конверторы: форма `data-convert="<кат>"`, поле `data-conv-in`, контейнер
  `[data-conv-results]`, стиль `.conv-row`.

### 3.3. Подводные камни вёрстки

- **Грид:** `.grid-column-main` ДОЛЖЕН быть ДОЧЕРНИМ к `.grid-column-left` (рядом с
  `.grid-column-sidebar`, тот же отступ — 4 таба), НЕ соседом. Иначе вёрстка ломается.
- **Одинаковые `name` у радио-единиц** на одной странице → одна радио-группа, выбор
  в одном снимает галку в другом. Давай уникальные `name`. Движок читает текст кнопки,
  поэтому устойчив, но лучше не создавать коллизий.
- **Выбор размера трубы:** радио `value` НЕ равен индексу таблицы. Движок резолвит
  диаметр по ЧИСЛУ в подписи (DN80→80, 25A→25), ища в `PIPE_TABLE` трубу с
  `parseInt(m)===num`. `data-type="size"`; поле `[data-var=pipeInDiam]` (если есть)
  переопределяет.
- **CRLF + двойные пустые строки** в некоторых `.pug` (напр. calc-2) ломают построчный
  Edit — правились node-скриптом (regex с захватом отступа).
- В `src/scss/main.scss` был случайный символ «1» (стр.33), ломавший SCSS — убран.

### 3.4. Калибровка (выполнена для 11110, ±0.06% по Δp на 9 эталонах)

Эталоны снимаются автоматически с toolbox.tlv.com той же формы. Драйвер: поля =
`input[type=text]` по порядку (0 давл, 1 темп, 2 расход, 3 потери, 4 длина, 5-8
фитинги, 9 шерох.), триггер `document.getElementById('calc').click()`, результаты в
`.outputText[0..4]`=[DN, d, v, Δp, Leq]. ⚠️ Расчёт АСИНХРОННЫЙ — задавать значения
с dispatch `input`+`change`, читать в СЛЕДУЮЩЕМ вызове (или конвейером).

Результаты калибровки (в `calc-formulas.js`):
- Трение: λ_TLV = 1.006 × Колбрук-Уайт (`FRICTION_CORR=1.006`).
- Фитинги — K-метод: L_eq = l + Σ(n·K)·d/f. K = {obsFlo(вентиль):10.5,
  thruFlo(задвижка):0.20, check(обратный):2.40, elbow(отвод):1.00}.
- ε по умолчанию 0.05 мм. Свойства пара по насыщению, если темп пустая.
