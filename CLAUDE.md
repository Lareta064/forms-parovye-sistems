# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команды

- `npm start` — clean → сборка → запуск BrowserSync на `./build` со слежением за файлами (Pug/SCSS/JS/изображения/шрифты). Основной режим разработки.
- `npm run build` — однократная продакшн-сборка в `./build`. Без watch и без сервера.

В проекте не настроены тест-раннер, линтер и форматтер. Конвейеры Pug и SCSS выводят ошибки компиляции через `gulp-plumber` + `gulp-notify` (системное уведомление), чтобы watcher не падал на синтаксической ошибке — фактическое сообщение смотрите в выводе терминала.

## Архитектура

Это статический сайт-генератор на Gulp 4 для русскоязычной коллекции опросных листов и инженерных калькуляторов для промышленных паровых систем. На выходе — обычные HTML/CSS/JS в `./build/`; никакого фреймворка, бандлера и клиентского роутинга нет.

### Конвейер сборки (`gulpfile.mjs`)

ESM-gulpfile. В начале файла находится единый источник истины — объект `paths`, описывающий все globs; задачи мапятся 1-к-1 на записи в `paths`. Что важно знать о поведении:

- **Pug** имеет две параллельных точки выхода: `src/pug/pages/**` → `build/*.html`, `src/pug/ui/**` → `build/ui/*.html` (отдельное дерево превью UI-кита). Оба используют `gulp-pug` с `pretty: true`, затем `gulp-format-html`.
- **SCSS** имеет одну точку входа: `src/scss/main.scss`. При добавлении нового partial-файла нужно вручную добавить строку `@use` в `main.scss` — глоб-импорта нет. Вывод — expanded-CSS с sourcemap + autoprefixer + `gulp-group-css-media-queries`.
- **JS** конкатенируется (не бандлится) в `build/js/main.js` в алфавитном порядке glob-выдачи. Никаких модулей, никакой транспиляции. Каждый файл в `src/js/` оборачивает логику в `DOMContentLoaded` и работает с обычным DOM API.
- **Изображения** обрабатываются по трём веткам: JPG/PNG → `imagemin` → `gulp-webp` (оригиналы НЕ копируются, в build попадает только `.webp`); SVG копируется как есть (без SVGO); остальное → `imagemin` → копирование.
- **Шрифты** обрабатываются по двум веткам: `.ttf` → `ttf2woff2`; уже готовые `.woff`/`.woff2` копируются без изменений.
- `libs/` и `video/` копируются массово без обработки.
- Задача `build` запускает всё параллельно после `clean`; задача по умолчанию добавляет сверху `server` + `watch`.

### Структура страниц

- `src/pug/pages/index.pug` — **главная-индекс** со ссылками на все формы и калькуляторы. При добавлении новой страницы нужно также добавить сюда карточку-ссылку.
- `index0.pug` … `index11.pug` — 12 отдельных опросных листов (по одному на промышленный компонент: конденсатоотводчик, регулирующий клапан, РОУ, эжектор и т.д.). Исходная спецификация для каждой формы — соответствующий `.xlsx` в папке `tables/` в корне репозитория.
- `calc-main.pug`, `calc-1.pug` … `calc-3.pug`, `calc-template.pug` — инженерные калькуляторы. `calc-template.pug` — стартовая болванка для новых калькуляторов.
- `src/pug/ui/` — самодостаточный UI-кит (кнопки, формы, сетки, типографика, иконки и т.д.), рендерится в `build/ui/` и подключён ссылкой с главной. Используйте его как визуальный референс при добавлении компонентов.

### Лейауты

Два лейаута в `src/pug/layouts/`, оба подключают `./css/main.css` и `./js/main.js` относительными путями (поэтому весь итоговый HTML обязан лежать в корне `build/` или в `build/ui/` — более глубокая вложенность сломает пути к ассетам):

- `layout.pug` — оборачивает контент в `.form-grey-wrapper`. Используется опросными листами (`index*.pug`).
- `layout-white.pug` — без обёртки. Используется калькуляторами (`calc-*.pug`).

Страницы задают `-var title = "..."` и могут инжектить кастомный `<style>` через `!{customStyle}`.

### Организация SCSS

`main.scss` подключает через `@use` partials из четырёх папок: `base/` (переменные, типографика, form grid, dropdown, иконки — фундамент дизайн-системы), `blocks/` (переиспользуемые компоненты: accordion menu, tabs, hide-block, calculator-formulas), `sections/` (лейауты уровня страниц, например `_calc-page`), `ui/` (стили специально для UI-кита). `_var.scss` форвардится как `*` и содержит общие токены.

### Общие блоки

`src/pug/blocks/_acc-menu.pug` — боковая аккордеон-навигация калькуляторов; подключается каждой страницей `calc-*.pug` через `include ../blocks/_acc-menu`. Поведение раскрытия/сворачивания — в `src/js/acordion-menu.js`.

`src/js/form-validate.js` отвечает за маску телефона (`+7(XXX)XXX-XX-XX`), применяемую к любому `input.phone`, а также за общую валидацию форм. `dropdown.js` управляет кастомным селектом `.dropdown`, который используется в выборе единиц измерения в калькуляторах. `hide-block.js` переключает условно показываемые секции в опросных листах.

## Соглашения, о которых стоит знать

- **Имена файлов с пробелами** существуют намеренно (`calc-1 copy.pug`, `calc-2 (1).html`). Не переименовывайте их автоматически — это незавершённые рабочие дубликаты, которые автор сохраняет.
- **Весь интерфейсный текст — на русском.** Сохраняйте исходные формулировки при правках; не переводите строки на английский.
- **JS-модулей нет.** `import`/`export` в `src/js/*.js` молча сломает сборку, потому что файлы просто склеиваются. Используйте IIFE или блоки `DOMContentLoaded`, как в существующих файлах.
- **Изображения, подключаемые из CSS/HTML, должны использовать `.webp`** для исходников jpg/png, так как оригинал в build не попадает.
